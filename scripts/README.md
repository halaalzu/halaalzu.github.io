# "Me!" carousel data

The four cards in the **Me!** section on the home page are fed by
`public/data/me.json`, which is regenerated by
[`.github/workflows/me-data.yml`](../.github/workflows/me-data.yml) every 6 hours
(and on demand from the Actions tab → *Refresh Me! carousel data* → *Run workflow*).

```
scripts/fetch-me-data.mjs    orchestrates the four sources, writes public/data/me.json
scripts/sources/*.mjs        one file per source
scripts/spotify-auth.mjs     one-time helper to mint the Spotify refresh token
scripts/lib/                 tiny RSS reader + .env.local loader, no dependencies
src/hooks/useMeData.js       front end loads /data/me.json, falls back to src/data/me.js
```

The site stays fully static — there is no server. If a feed is down, that card
keeps its previous value (the script merges over the committed `me.json`) and
records the failure under `sources` in the JSON.

Run it locally any time:

```bash
npm run me:fetch
```

## Sources

| Card | Source | Auth |
| --- | --- | --- |
| Hero quote | Goodreads saved-quotes page (`/quotes/list/<id>`) | none |
| Currently reading | Goodreads `currently-reading` shelf RSS | none |
| Top 5 this month | Spotify top tracks, `time_range=short_term` | refresh token |
| Last watched | Letterboxd member RSS (latest diary entry) | none |
| Recently saved | Pinterest RSS (`/<user>/feed.rss`) | none |

The Spotify card's ‹ › buttons cycle those top 5 in order; each shows its rank.

## Configuration

### Local

Credentials live in `.env.local` (gitignored, never committed):

```
SPOTIFY_CLIENT_ID=...
SPOTIFY_CLIENT_SECRET=...
SPOTIFY_REFRESH_TOKEN=...      # written for you by me:spotify-auth
GOODREADS_USER=halaalzu
LETTERBOXD_USER=halaalzu
PINTEREST_USER=halaalzu
```

### CI

Usernames are **repository variables** (Settings → Secrets and variables →
Actions → *Variables*). Each defaults to `halaalzu`, so only set the ones that
differ:

| Variable | Default |
| --- | --- |
| `GOODREADS_USER` | `halaalzu` |
| `GOODREADS_SHELF` | `currently-reading` |
| `GOODREADS_QUOTE_LIMIT` | `60` (how many saved quotes to keep in `me.json`) |
| `LETTERBOXD_USER` | `halaalzu` |
| `PINTEREST_USER` | `halaalzu` |
| `PINTEREST_BOARD` | *(empty — set it to pin the stack to one board)* |
| `SPOTIFY_USER` | *(empty — only used for the profile link)* |

Spotify credentials are **repository secrets**: `SPOTIFY_CLIENT_ID`,
`SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REFRESH_TOKEN`.

The workflow also needs Settings → Actions → General → Workflow permissions set
to **Read and write**, or it cannot push the refreshed `me.json`.

### Connecting Spotify

1. Create an app at <https://developer.spotify.com/dashboard>.
2. Add `http://127.0.0.1:8888/callback` as a redirect URI.
3. Put `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` in `.env.local`.
4. `npm run me:spotify-auth` → open the printed URL → approve. The refresh token
   is written back into `.env.local` automatically.
5. `npm run me:fetch` to confirm, then copy the three values into repository
   secrets for CI.

Scopes requested are read-only: `user-top-read`, `user-read-recently-played`,
`user-read-currently-playing`.

## Notes

- Goodreads' RSS is keyed by numeric user id; the script resolves the vanity
  URL (`goodreads.com/halaalzu`) to that id automatically.
- The hero quote rotates on every page load and every time you scroll back up to
  the hero (`src/hooks/useRotatingQuote.js`), picking at random from **every**
  quote saved on Goodreads. Save a new one there and it appears after the next
  refresh — no code change. Quotes come from the HTML page rather than the quotes
  RSS feed, because only the HTML carries the book each quote is from; the book
  id in `quote_book_link_<id>` is the `/book/show/` id.
- Letterboxd's feed only carries **diary entries** — films you have logged as
  watched. Watchlist additions are not exposed over RSS (that endpoint 403s).
- Spotify only returns a 30-second `preview_url` for some tracks. When it is
  missing, the play button still spins the vinyl — there is just no audio.
- `time_range=short_term` is Spotify's own "last 4 weeks" window; it needs a bit
  of listening history before it returns anything, so the script falls back to
  recently-played on a new account.
- The workflow builds and deploys to Pages itself, because a push made with
  `GITHUB_TOKEN` does not trigger `deploy.yml`.
